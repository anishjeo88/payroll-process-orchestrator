## Reading these honestly

This is a small demo, not a production deployment, so several of these
"FAIL"s are a sample-size artifact rather than a real quality problem -
worth being explicit about which is which:

- **Escalation Accuracy / Human Override Rate — n/a.** Nobody has clicked
  Approve/Reject on the seeded cycle's pending items yet. Both metrics
  activate the moment you decide the first one (interface/pages/
  3_Approvals.py); they measure whether the Escalation Decision Agent's
  Tree-of-Thought picks hold up under human review, so they're only
  meaningful once there's a real decision history to compute over.
- **Retrieval Relevance Score (0.60, target 0.80) — a real, if
  small-sample, finding.** The demo corpus is 4 documents
  (agents/knowledge_retrieval.py's `_CORPUS`). One of the 4 sample queries
  ("SOX control review compliance requirements") only scores 0.32 - the
  Compliance Handbook chunk it should match doesn't use that exact
  phrasing. A larger, more varied corpus would likely close this gap; it's
  flagged here rather than hidden.
- **Fallback Rate (100%, target <15%) — expected given only 2 escalations
  exist.** Both happen to be Tier 2/Tier 3 (Benefits Data Feed Validation,
  the Compliance Sign-off), so both correctly needed human review under the
  Tier 1 autonomy ceiling. This metric is only informative at a larger n;
  with n=2 it's not evidence of miscalibration.
- **Cycle Step On-Time Rate (88.9%, target 95%) — the one metric with a
  real, larger sample (18 steps across 2 closed historical cycles), and a
  genuine finding**: `2026-08A` had a 2-day slip on Benefits Data Feed
  Validation that needed a Tier 2 escalation (see
  [History](../interface/pages/4_History.py)); `2026-08B` was clean. This
  matches the known delay pattern on file for that step
  (`environment/seed_data.py`'s `DELAY_PATTERNS`).
- **Groundedness Rate / Notification Duplicate Rate — PASS, and actually
  enforced, not assumed.** Groundedness is a live self-test each run (calls
  the real guardrail with and without a backing tool-call result and
  confirms both the pass and the block). The duplicate rate reads real
  sent-alert history; it's structurally low because
  `guardrails/static_constraints.py`'s dedup check blocks a repeat before
  it's ever logged - see `evaluation/metrics.py`'s docstring for exactly
  what each metric measures and why.
